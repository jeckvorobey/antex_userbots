## Why

При запуске каждый userbot повторно перебирает все Telegram-диалоги для каждой включённой группы, а runtime-кэш хранит entity только одной последней группы. С ростом числа групп это создаёт лишние сетевые обходы при startup и на каждом scheduler tick.

## What Changes

- Один раз индексировать доступные Telegram-диалоги каждого userbot перед проверкой всех включённых групп.
- Переиспользовать индекс при membership-проверках и обновлять его после успешного вступления.
- Хранить resolved entity в раздельном кэше по ключу группы вместо одного перезаписываемого значения.
- Сохранить последовательный запуск userbot и случайную задержку 30–60 секунд, чтобы не создавать одновременный всплеск подключений и membership-запросов.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `swarm-runtime`: membership-проверки должны переиспользовать единый индекс диалогов на userbot, а резолвинг нескольких групп — независимый кэш каждой группы.

## Impact

- `run.py`: поиск доступных групп, startup membership hook и кэш resolved target.
- `tests/test_runtime.py`: проверки числа обходов диалогов, обновления индекса после join и изоляции кэша групп.
- Публичные настройки, база данных и порядок запуска userbot не меняются.
