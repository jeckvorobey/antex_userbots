## Context

После membership check startup hook уже имеет entity каждой целевой группы, но не проверяет права текущего аккаунта на отправку сообщений.

## Goals / Non-Goals

**Goals:**

- При startup логировать итоговый `can_write` для аккаунта в каждой группе.
- Логировать исходные Telegram-параметры, из которых получен итог.

**Non-Goals:**

- Не запрещать запуск или отправку сообщений.
- Не менять membership, права Telegram или расписание.

## Decisions

- Запрашивать пользовательские и default banned rights через Telethon `get_permissions` после membership check. Это даёт актуальные права именно подключённого аккаунта.
- Считать `can_write` ложным при запрете `send_messages` для участника или для группы по умолчанию, кроме администратора. В лог выводить все три значения.
- Если Telegram не вернул права, логировать `can_write=unknown` и продолжать startup, поскольку это только диагностика.

## Risks / Trade-offs

- [Дополнительные запросы Telegram при startup] → Запросы выполняются один раз на аккаунт и группу после уже существующей проверки membership.
- [Не удалось прочитать права] → Startup продолжится, а warning покажет причину отсутствия диагностики.
