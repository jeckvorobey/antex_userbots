## Why

Multi-group runtime still uses one shared `topics.md`, but the current topic file contains city-specific ready-made questions. That can send questions about one city into another city's group.

## What Changes

- Treat `topics.md` as a shared list of universal topic intents, not ready city-specific questions.
- Make `start_topic.md` responsible for adapting a shared intent into one natural question for the current group city.
- Keep anti-repeat group-scoped, so the same universal intent can be used independently in different cities.
- Remove unused `reply_rules.md`.
- Replace committed `*.example.md` templates with real prompt files for the single production instance.
- Update `.gitignore`, tests, README, and OpenSpec docs so real prompts/personas/topics are tracked instead of ignored.

### New Capabilities

### Modified Capabilities
- `prompt-and-gemini`: shared topic intents, city-aware start-topic generation, real tracked prompt files, no unused prompt rules file.
- `runtime-configuration`: prompt files are production config files for this single instance, not local copied examples.
- `scheduled-exchanges`: scheduled questions are generated by adapting shared intents to the target group city.

## Impact

Affected areas include prompt files under `ai/prompts/`, `.gitignore`, prompt-related tests, README/config docs, and prompt OpenSpec specs. Runtime code changes should be minimal because the existing orchestrator already passes group context into prompt composition.
