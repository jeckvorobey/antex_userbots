# usbttg — UserBots

Асинхронные Telegram UserBots на Telethon, OpenRouter и SQLite. [README.md](README.md) описывает настройку, [docs/development.md](docs/development.md) — архитектуру, пути и проверки. Читай только разделы затронутой подсистемы.

## Инварианты

- Только `aiosqlite` и SQLite; без синхронного DB API, FastAPI/HTTP-сервера, PostgreSQL или Redis.
- Persona загружается из `persona_file`; промпты хранятся в `ai/prompts`. Сообщения сохраняются в БД. Не меняй эти контракты без соответствующей задачи.
- Не выводи и не коммить `SESSION_STRING_*`, `OPENROUTER_API_KEY`, Telegram `api_hash`, proxy credentials и пользовательские данные.
- Мокируй OpenRouter SDK и Telethon, используй изолированную SQLite в тестах. Запуск runtime может отправлять сообщения и вызывать платную генерацию; он требует отдельного основания в задаче.
- Сохраняй текущий checkout, несвязанные изменения, production-конфигурацию и расписание. Commit/push/deploy выполняются только в разрешённом scope.

## Изменение и проверка

Сначала исследуй код и существующие тесты. Для изменения поведения добавь релевантный сценарий и проверь его; для инструкций/документации не запускай runtime или формальный TDD. Применяй полный набор проверок при влиянии на общие контракты либо другом подтверждённом риске.

Для новых функций и изменений архитектуры, API, БД или формата данных используй общий `openspec` Skill и существующий change. Разрешённая реализация может включать подготовку нужных артефактов без повторного согласования того же scope. Sync/archive выполняй, когда они входят в согласованное завершение; passing tests не разрешают внешнюю доставку. Малые правки без изменения контрактов не требуют отдельного change.

Общие Skills находятся в `~/.agents/skills/`; не загружай FastAPI/Quasar для этого runtime. В результате различай локальные проверки, live Telegram, AI-генерацию и production; указывай только фактически полученные доказательства.
