## Context

Текущий алгоритм строит новый список кандидатов для каждого prefix recent bot history.

## Goals / Non-Goals

**Goals:**

- Уменьшить число проходов roster с `O(k*b)` до `O(k+b)`.
- Сохранить точный порядок списка кандидатов и fallback cooldown.

**Non-Goals:**

- Не менять размер cooldown и стратегию случайного выбора пары.

## Decisions

- Учитывать количество профилей по id и количество повторов id в prefix history; это сохраняет текущую семантику set-исключения даже при дубликатах history.
- Создавать список кандидатов только после нахождения максимального допустимого cooldown.

## Risks / Trade-offs

- [Повторы bot id в history] → Счётчики не возвращают id в пул, пока удалён весь prefix этого id.
