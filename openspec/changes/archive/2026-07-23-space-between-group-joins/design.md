## Context

В `run.py` multi-group startup hook после одной случайной задержки 30–60 секунд последовательно вызывает `_ensure_group_membership` для enabled-групп. Если группа уже доступна, вызов завершает только membership check; если доступа нет, он выполняет join. Сейчас между соседними итерациями нет паузы.

## Goals / Non-Goals

**Goals:**

- Ввести константу фиксированного интервала `20.0` секунд.
- Ждать этот интервал перед каждой enabled-группой, кроме первой обрабатываемой группы.
- Сохранить последовательную обработку групп, текущую задержку 30–60 секунд перед циклом и single-group hook без дополнительной паузы.
- Зафиксировать порядок вызовов и значения задержек async-тестом без реального ожидания.

**Non-Goals:**

- Не добавлять настройку интервала в TOML или `.env`.
- Не менять случайную задержку 30–60 секунд.
- Не запускать membership checks или join-запросы параллельно.
- Не менять Telegram API wrapper, persistence или reload flow.

## Decisions

1. Пауза реализуется в `_build_multi_group_membership_startup_hook` перед `_ensure_group_membership` начиная со второй enabled-группы. Это гарантирует интервал между последовательными операциями и не создаёт лишнюю задержку после последней группы.
2. Счётчик будет относиться к реально обрабатываемым enabled-группам, а не к их индексам в исходном списке. Поэтому отключённые группы не вызывают ни membership operation, ни ложную паузу.
3. Используется `asyncio.sleep(GROUP_JOIN_INTERVAL_SECONDS)`, чтобы не блокировать event loop. Тест подменяет sleep и проверяет вызовы.

## Risks / Trade-offs

- [Startup одного userbot с несколькими группами станет дольше] → интервал применяется только между группами; single-group startup и уже существующая начальная задержка не изменяются.
- [Пауза будет применена и когда предыдущая группа уже была доступна] → это сохраняет консервативный интервал между любыми последовательными membership operations и не требует раскрывать внутренний результат `_ensure_group_membership`.

## Migration Plan

Изменение не требует миграции конфигурации или БД. После обновления процесса новый startup hook автоматически использует интервал 20 секунд; rollback — возврат изменения hook и теста.
