## Context

Оркестратор scheduled exchange уже использует group-scoped anti-repeat: `ExchangeStore.get_recent_bot_ids()` возвращает N последних уникальных ботов по событиям в конкретной группе. Текущий `RECENT_BOT_COOLDOWN_LIMIT = 3`. Пользователь хочет расширить cooldown до 4 ботов, чтобы в одной группе одни и те же боты возвращались в обмен ещё реже.

## Goals / Non-Goals

**Goals:**
- Увеличить anti-repeat cooldown с 3 до 4 последних уникальных ботов в каждой группе.
- Сохранить существующую деградацию: если после исключения 4 ботов остаётся < 2 кандидатов, постепенно ослаблять фильтр.
- Подтвердить group-scoped изоляцию: история другой группы не влияет на выбор.

**Non-Goals:**
- Не менять SQL-запрос `get_recent_bot_ids` — он уже group-scoped.
- Не менять схему SQLite или формат данных.
- Не менять логику topic/question anti-repeat.

## Decisions

### Константа вместо конфигурации

`RECENT_BOT_COOLDOWN_LIMIT` остаётся константой в `orchestrator.py`, а не выносится в TOML. Причина: значение управляется разработчиком, а не оператором; вынос в конфиг добавит complexity без пользы.

### Изменение одной строки

Повышение `RECENT_BOT_COOLDOWN_LIMIT` с 3 до 4 — это изменение одной константы. SQL-запрос, `_pick_bot_candidates` и деградация работают без изменений, т.к. параметр `limit` передаётся динамически.

## Risks / Trade-offs

- **Маленький пул ботов** → при 4-5 ботах cooldown 4 оставит 0-1 кандидата. Mitigation: деградация в `_pick_bot_candidates` уже обрабатывает этот случай.
- **Тесты с хардкодом 3** → нужно обновить тесты, которые ссылаются на 3 как на размер cooldown. Mitigation: обновить тесты.
